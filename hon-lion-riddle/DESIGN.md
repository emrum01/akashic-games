# 仕様の出典と現行範囲

## 渡された設定

出典: ユーザーが参照先チャットで実装元として指定した `/Users/hirokiiwakubo/Github/game-mvp.md` の「真相の判定」「音」「戦闘」。参照先: `codex://threads/01a0c408-690f-73a3-952c-42890d2110bf`。この会話の追加指定により、カメラの設定は病院での撮影とし、その説明は正解の必須条件から外す。

1. 洋館は幻覚である。
2. プレイヤーの視点は、病院で自分の耳の中を映しているカメラの映像である。
3. 耳に入り込んだ虫が、自分の脳を食べている。
4. 心地よく聞こえていた音は、その捕食音である。

虫を焼く操作は、現実では耳かきによる除去に対応する。現実のレーザー治療という設定ではない。虫の除去で音の一部が消え、全駆除で咀嚼音が止まる。本ライオンは、正体が虫の会話相手ではない。

正解に必要なのは1・3・4の三点。「病院」「カメラ映像」を回答に含めなくても正解とする。これらは質問には答えられる真相として保持する。

## 元資料でも未定のこと

- 現実で耳かきを操作している人物。
- 入口の向こうの声の主。
- 耳を確認し始めた理由。

これらを創作で埋めたり、正解の必須条件にしたりしない。

## この会話で指定された進め方

- 本ライオンとの水平思考ゲーム。通常の返答は「はい」「いいえ」「関係ない」の三択。
- 導入は2026-10-20のユーザー指定文を使う。仕事帰りにASMRを聴く習慣、入眠、洋館での目覚めを暗い画面で順に表示し、指定の「ここから洋館の画面」の位置で背景と本ライオンを表示する。同じ音がイヤホンではなく奥の廊下から聞こえる描写、本型のライオンの発見へ続ける。本ライオンの自己紹介は指定文のまま使う。
- 本ライオン発見の文章まで読み進めた後、本ライオンをクリックすると、指定の自己紹介を会話欄に表示する。導入中は表示のみとし、自己紹介で本文を中断しない。
- 導入後、質問を始める前に問題文を一枚表示する。「この洋館と、聞こえ続ける音の正体は何か。あなたの身に何が起きているのかも含めて、状況を説明してください。」とし、答える三点を明確にする。最終推理の入力欄にも三点を示す。問題文を読む時間は制限時間に含めない。
- 推理が進むと奥へ進む。どの核心から理解してもよく、特定の質問順を必須にしない。
- 謎を解いて鍵をもらい、戸棚から入手する巨大な光線銃で開かずの間の虫を焼いてクリアする。
- 調査ボタン、引き出しを開ける操作、持ち物管理は不要。入手はアイテム画像とメッセージで表示する。
- 背景は指定された3D空間で制作した歩行動画。キャラクターは提供画像を参考にした立ち絵。
- 移動ではゆっくり歩く上下動を付け、壁や家具を通り抜けず、過剰な視点の微調整を避ける。
- 部屋に入る前に一度止まり、その次に椅子の前へ進む。到着時はランプ・椅子・右上の十字架が一緒に見える指定構図。
- 開かずの間の入口には、元の空間の入口の扉を使う。
- 素材の収録時には、指定されたハシゴとその近くの雪だるま状の立体を除去する。
- TypeSafe JEVを実際の会話・推理判定に使う。

ゲームの正式タイトル、追加の話者名、個々の地点で提示する具体的な手がかりや台詞は未確定。「水平思考ゲーム」はブラウザのタイトルとアクセシビリティ上の見出しに限り、画面へ重複表示しない。

## 今回の実装整理

真相のデータは `worker/src/scenario.ts` に置く。最終推理は必須の三点（幻覚・耳の虫による自分の脳への捕食・音の正体）をJEVで個別に意味判定し、ゲーム側で合成する。病院やカメラ映像の説明は要求しない。単語の有無だけで正解にしない。通常質問だけでは鍵を発行しない。

推理の進行は、新しい核心の確認を積み重ねて既存の移動地点へ反映する。一つ目で部屋の入口手前、二つ目で椅子の前へ進む。核心同士の関係を一度に確認した場合も椅子の前まで進める。同じ理解の繰り返しでは進めない。特定の核心を特定の順に答える条件は置かない。

元資料の自由探索・脚立操作・複数NPC・襲撃戦闘を、この会話ゲームへ自動で追加しない。新しい証拠や出来事を補作して完成扱いにしない。

## 演出の改善と確認基準

- 開始の操作から、小さな齧る音と、その最中に動く擦れ音の反復を流す。実録の咀嚼音を主素材にし、26秒に5つの塊で配置する。真相判明や移動の前後で同じ音・同じ音量を使い、虫を除去した瞬間に止める。消音はウィンドウ内のアイコンで切り替える。常設の字幕は置かない。
- 開始画面は「はじめる」だけにする。キャッチコピー、ルール一覧、補足説明、デモ表示、照準合わせの実況、クリア時のあらすじは表示しない。移動後の観察は下記の一度だけとし、質問数による自動ヒントは追加しない。
- ノベルゲームのように、背景と立ち絵の上へ一枚の横長の半透明ウィンドウを重ねる。明朝体、角のある薄い枠、名前と一つの本文を使い、ボタンの塗りや重ねたカードは使わない。参考は『うみねこのなく頃に咲』の公式ゲーム画面（https://www.entergram.co.jp/umineko/outline.html）。作品の画像や装飾を配信素材へ流用しない。
- 質問・推理の入力は必要なときだけ開き、本文と入れ替える。送信後は返答の一文だけを見せ、質問文と履歴を積み上げない。判定用の会話文脈は保持する。
- 最終推理は複数行で入力できる。質問と推理の下書きは別々に保存し、「戻る」で本文へ戻れる。不足した推理は「推理を直す」から再編集でき、通信エラーでは入力を復元する。
- 入力ラベルはアクセシビリティ用に残す。通常の操作、消音、次へ進む操作はウィンドウ下部へまとめる。読み進める操作は小さな三角で示す。必要なエラーだけは本文の近くに表示する。
- 正解、鍵、戸棚からの光線銃の入手、虫との対峙を一つずつ見せる。入手したアイテムの画像と本文は横並びにする。持ち物HUDや調査操作は追加しない。
- 対峙では本ライオンを退かせ、実画像の虫と光線銃を見せる。発射、虫の除去、音が止まる間、幻覚の消失、脱出成功を順番に見せる。
- 元の入口に到着後、同じ元モデルの扉が開く動画を再生し、開き終わってから虫を見せる。銃口の位置と虫の中心から照準と光線の線を計算する。
- 虫の幻覚は、虫の形にこだわらず、白い輪状の体と二本ずつの手足を持つお茶目な人型として見せる。光線銃は、スライド・グリップ・トリガーガードが分かる巨大なハンドガン型にする。部屋の質感に合う無骨な金属製の3D調とし、手前から奥へ構える一人称の画像を使う。横向きの画像を回転させて構える表現にはしない。
- 対峙の画像は読み込み前から縦横比を確保し、読み込み後にも照準を合わせる。砲口と相手が重ならない余白を設ける。
- 再開やページ離脱では、音、虫、ビーム、遅延中の演出、会話、下書き、移動進捗を初期化する。
- 本ライオンとの質問画面に入った時点で一度だけ20分（1,200,000ms）の壁時計タイマーを開始する。タブがバックグラウンドにあっても期限は進み、表示へ戻った時と各操作・応答境界で期限を検査する。5分・10分・15分・18分・19分30秒で低コントラストの画面ノイズを段階的に強める。
- ノイズが現れるときと段階的に強まるたびに「思考力が下がったような気がする。」と表示する（5分・10分・15分・18分・19分30秒）。入力中・返答待ちには割り込まず、操作が終わってから出す。同じ段階での再検査では重複させず、前回の同文を隠して再表示する。死亡後の遅延表示は行わない。
- 20分までに虫を除去できなければ、虫・本ライオン・光線銃を隠して暗い時間切れ画面へ移り、短い死亡文と再プレイ操作を表示する。期限後に到着する応答・画像・移動・ビームのコールバックは世代番号で無効にする。虫が実際に消えた時点でタイマーとノイズを止め、再プレイでは期限・ノイズ・進行を初期化する。
- 最初の核心での移動が実際に到着した後、一度だけ「あれ、進んでも音が大きくならない。」という観察を、質問入力や返答を上書きしない次の短いビートとして表示する。片耳の感覚や、音源の場所を決めつける説明は加えない。
- 期限とノイズ段階は `app/deadline.js`、到着・思考力低下の台詞の保留と取消は `app/observation.js` に分離する。バックグラウンドで複数段階を経過した場合も各段階の台詞を保留する。移動中に最終正解や報酬操作へ進んでも、実際の到着後に一度だけ観察を表示し、報酬・入室のボタンを消さない。
- 判定リクエストは直近6件の履歴と、サーバーが返した最大4件の`knownInsights`をクライアントの実行中メモリで持ち回る。既知の核心と同じ質問はサーバー側で進捗を増やさず、言い換えの意味判定はJEVへ委ねる。リプレイやBFCache復元ではこの文脈も初期化する。
- オフライン確認用のデモ判定は公開アプリへ置かず、`npm run dev`がlocalhostのWorkerへ明示的に渡すフラグと`?demo=1`で有効にする。Workerにキーがある場合はフラグよりライブJEVを優先する。
- 報酬画像は読み込み成功を待つが、エラーや有限時間のタイムアウトでも文章の導線を開ける。入口への移動は画像の状態と独立して、シーン到着を待つ。
- 入口手前、椅子の前、元の入口の動画と構図は変更しない。病院での人物や現実の操作者を追加描写しない。

演出は大小の画面で一周し、入力・報酬・標的・次の操作が欠けないこと、実際のJEVとの三択会話、正解の三条件、途中の誤答と再開を含めて再確認する。
