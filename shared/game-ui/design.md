## 操作と説明

目標・操作面・状態を各一箇所にまとめる。自明なボタン順を本文で繰り返さず、隠れた制約と操作の使い分けは省かない。短さ自体は目的にしない。

初見に専門知識を仮定しない。新しい道具を使う謎は **対象の前提 → 道具で分かること → 目標と回数制限** の順で導入する。天びんでは既存の遊び方3ページを初回に一度開く。resetでは繰り返さず、閉じると入力欄ではなくコインへfocusを戻す。「8枚のうち2枚が重い」「二皿の重さを比較できる」「2回の結果で特定する」を先に説明する。隣接・重さの等しさ・8と1の関係も省かない。文法のlint合格は、概念理解や謎の面白さの合格ではない。

遊び方は最大3ページ。通常320×568・390×844、16pxでページ内スクロール不要を目標に実測。200%文字では拡大を優先し、必要なスクロールを許す。Dialogはfocus・Escape・背景操作抑止・戻り先を維持。Tab順から不要要素を除く。

タップ目標は44px以上。主操作同士は12–16px、セクションは24px程度を確保する。指から始まるドラッグとページのスクロールを分ける。静的紙片の安定したtouch領域・非passive listener・Undo・回収・半透明ハンドルを維持する。キーボード、IME、入力中の最初のタップ、狭い可視viewportの保護を維持する。Chromiumのtouch検査を実機WKWebViewの成功と呼ばない。
